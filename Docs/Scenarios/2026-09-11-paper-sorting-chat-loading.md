# 논문 정렬 및 긴 채팅 전환 검증

## 변경

- 이름 오름차순, 업로드 최신순, 최근 사용자 채팅순. 선택은 앱 재시작 후에도 유지한다.
- 최근 채팅 메타데이터는 최초 조회 후 캐시하며 전송·재시도 후 저장된 사용자 시각으로 갱신한다.
- SwiftData는 paperID로 메시지를 필터링하고, UI 밖에서 조회한다.
- 첫 화면은 최근 40개를 표시한다. 이전 기록과 과거 질문은 요청할 때 펼친다.
- 질문 탐색 막대의 높이는 최대 320pt로 제한한다. 수식 메시지 자체는 eager VStack을 유지한다.

## 결과

400개 메시지(수식 assistant 200개)를 같은 프로덕션 SwiftUI View와 메모리 fixture로 비교했다.
기존 방식은 임시 추출 View의 메시지 루프만 전체 기록으로 바꾼 대조군이다.

| 항목 | 전체 기록 렌더 | 최근 40개 렌더 |
| --- | ---: | ---: |
| 초기 수식 WKWebView 수 | 200 | 20 |
| 초기 레이아웃 시간 | 10,274ms | 1,386ms |

이벤트 사이 의도적인 대기 시간을 성능 수치에서 제외했다. 단일 로컬 실행이며 실제 사용자
채팅 전환의 종단 간 지연이나 디스플레이 FPS 수치가 아니다.

정렬·동률·설정 저장 검사, 표시 범위 및 반복 전송 실패 검사, 기존 관성 제스처 1,000회 및 일반·수식
실제 View 검사 통과. SwiftData 메모리 저장소에서 타 논문 메시지 2,000개를 포함한
백그라운드 조회의 대상 격리·정렬·빈 결과 검사 통과. 전체 Xcode release 앱 빌드·서명, ChatMathTests 26/26, Gate0GTests 16/16도 통과했다.
실제 사용자 채팅은 전송하지 않았다.
실제 사용자 창의 이전 기록 버튼 클릭은 자동화하지 않았으며 해당 범위 계산과 렌더를 검증했다.
