## 발견한 문제와 해결

SwiftUI contextMenu를 WebView 전체에 적용하면 처음에는 수식이 나타나지만 스크롤 후
내용이 빈칸으로 바뀌었다. 이를 제거하고 NSView의 willOpenMenu에서 원문 복사 항목을
추가하자 스크롤·너비 변경 후에도 정상 표시됐다. 앱 빌드에는 KaTeX resource bundle도
명시적으로 포함해 개발 환경의 절대 빌드 경로에 의존하지 않는다.

UI 테스트는 `.build/scenarios/chat-math/ui-library`의 격리 라이브러리에서 진행했다.
사용자 라이브러리는 수정하지 않았다. 실행 로그는 `.build/scenarios/chat-math`에 있다.
전체 LaTeX 엔진은 아니며 KaTeX가 지원하지 않는 확장 명령은 원문으로 표시한다.

## 후속 채팅 스크롤 수정

수식 메시지 위에서 세로 휠 입력이 WebKit 내부에 머물러 채팅 스크롤바가 1에서 변하지 않는
문제를 실제 사용자 채팅에서 재현했다. 메시지 여백에서는 이동했다. 세로 이벤트를 바깥
채팅 스크롤뷰로 전달하고 네이티브 수식 뷰를 VStack에 유지했다. LazyVStack 사용 시 드러난
왕복 스크롤 후 빈 메시지도 해소했다. 자동 하단 이동은 하단 근처에 있을 때로 제한했다.

수정 앱에서 수식 위로 스크롤, 여러 메시지 왕복, 수식 내용 유지 확인 PASS.
ChatMathTests 25/25, Gate0ETests 30개 그룹 및 release 빌드 PASS.
검증 로그: `.build/scenarios/chat-scroll`. 사용자 메시지 추가·수정 없이 검증했다.
실제 응답 스트리밍 타이밍 및 대규모 채팅 이력의 메모리 부하는 이번 검증 범위에 포함하지 않았다.

## v1.0.1 hotfix: 개별 메시지의 세로 스크롤 차단

`hotfix/1.0.1`에서 WebKit 문서의 높이를 웹뷰에 고정하고 overflow를 clip으로 설정했다.
본문의 자연 높이는 계속 측정하며, 대각선 입력의 세로 성분도 바깥 채팅에 전달한다.
실제 WebKit의 320×80 viewport 회귀 검사에서 긴 메시지의 내부 세로 위치는 0으로 유지되고,
긴 블록 수식의 가로 이동은 유지됐다. 높이 고정과 clip을 제거한 negative control에서는
내부 세로 이동이 재현됐다. ChatMathTests 26/26, Gate0ETests 30, Gate0GTests 16 그룹 통과.
직접 UI 제스처 재검증은 화면 제어 도구의 캡처 오류로 제한됐다.

## 반복 스크롤 끊김 후속 수정

`hotfix/scroll-stutter`에서 메시지별 이벤트 모니터를 공용 모니터 하나로 통합했다.
매 픽셀 좌표 변화가 전체 채팅 View를 무효화하지 않도록 비관찰 저장소를 사용하고,
질문 필터·번호 매핑은 View 평가당 한 번만 계산한다. 스크롤 종료가 다른 메시지 위에서
발생해도 같은 채팅에 전달한다.

실제 앱 라우터를 컴파일한 검사에서 위·아래 입력 10,000개가 정확히 한 번씩 전달됐으며,
대각선·메시지 경계를 넘는 종료·가로 입력·다른 View 격리 검사도 통과했다.
ChatMathTests 26/26, Gate0GTests 16/16, release 앱 빌드·서명 검증 통과.
이 검사는 실제 디스플레이 프레임 속도 측정이 아니며, 직접 UI 재현은 캡처 도구 오류로 제한됐다.
로그는 `.build/scenarios/scroll-stutter`에 보관한다.

## 트랙패드 관성 중단 재검증

사용자 재현 조건은 수식 유무와 무관하게 손을 뗀 뒤 관성이 멈추는 현상이다.
기존 10,000회 전달 검사는 전체 제스처 단계와 실제 스크롤 위치를 검사하지 않아 이 문제를
배제할 수 없었다. 기존 라우터는 손을 뗀 `phase.ended`에 대상을 지우고 매 이벤트의
현재 메시지를 기준으로 전달 여부를 결정했다.

채팅 영역에서 시작한 제스처 대상을 관성 종료까지 유지하도록 변경했다. 수식 유무와
관계없이 OS의 세로 이동량을 같은 NSClipView에 직접 적용해 별도 네이티브 추적 루프에
재진입하지 않는다. 가로 제스처는 원래 responder에 전달한다.

`python3 Scripts/verify-chat-scroll.py` 최종 결과:

- 전체 제스처 1,000회, 이동량 없는 시작, 손 떼기, 메시지 경계를 넘는 관성, 가로 입력,
  채팅 밖 시작 및 제거 시 격리, 상하단 경계와 역방향 이동, 초기 가로 흔들림: PASS.
- 실제 생산 코드의 SwiftUI 채팅 View + 메모리 fixture: 일반 메시지 60개와 수식 포함
  메시지 20개 각각 94개 이벤트. 위치는 시작 0 → 손 떼기 360 → 관성 종료 840pt: PASS.
- 이벤트 처리와 동기 레이아웃·표시 소요 p95: 일반 3.20ms, 수식 2.48ms.
  이벤트 사이 의도적인 대기 시간은 제외한 값이며 디스플레이 프레임 속도가 아니다.
- ChatMathTests 26/26, Gate0GTests 16/16, release 앱 빌드 및 서명 검증: PASS.
- 수정 앱을 정상 재시작하고 새 바이너리 경로와 시작 시각을 확인했다.

합성 NSEvent를 라우터에 전달하는 실제 View 검사이며 물리 트랙패드에서 WindowServer를
거쳐 들어오는 입력 전체를 검증한 것은 아니다. 사용자 허용 후에도 화면 캡처 및
System Events 접근은 OS 권한으로 제한됐다. 사용자 채팅은 전송하지 않았다.
로그와 생성된 검사 View는 `.build/scenarios/scroll-render`에 보관한다.
